# Core packing-profile dependency and integration assessment (31 Oct 2026)

## Findings (evidence)
1. **Which Core interface supplies carton eligibility today?** None. Read-only queries on the live project (`tcxvcatsqqertcnycuop`, SELECT only) list every function and table whose name contains "carton" or "packing": all are dispatch, factory, Trace, finance or 3PGS material objects (`b2b_dispatch_cartons`, `dispatch_cartons`, `ols_cartons`, `ols_dpl_cartons`, `packing_lists`, `trace_*carton*`, `lock_/mark_/release_*dispatch_carton*`, …). There is no buyer-facing packing-profile or carton-configuration projection.
2. **Does an implementation exist elsewhere?** No packing-profile or carton-configuration contract exists in any accessible repository (Core `main` at `20708e7`, Central, AI Studio, Trace) or among the 121 remote Core branch names; the only branch with "carton" in its name (`cursor/point100-carton-ready-invoice-ist-69f8`) concerns dispatch/invoice authority, not buyer packing, and was inspected without modifying the Core clone.
3. **Required fields and permissions:** specified in `CORE_PACKING_PROFILE_CONTRACT_SPEC.md` (v1): two tenant-gated, read-only SECURITY DEFINER RPCs (`buyer_carton_configurations_v1`, `buyer_packing_profiles_v1`), zero rows unless the caller is an eligible approved buyer company, approved and currently effective rows only, no dimensions, weights, prices or approver data.
4. **Does the Buyer consume it correctly?** Yes at contract level: `packing-profile-contract.ts` fails closed (unknown version, duplicates, UOM mismatch, unapproved or ineffective rows, unsupported conversions) and feeds the carton engine; `carton-contract-integration.test.ts` runs spec-shaped payloads for all three cartons through normalisation, carton selection, view models, geometry and rendering; `carton-journey.test.ts` covers the whole pure-logic journey. These use synthetic fixtures against the **proposed** contract, not live Core.
5. **Authenticated end-to-end environment?** Not available: the project's only branch is the #399 release-train preview with `MIGRATIONS_FAILED` and no data, and no buyer credentials are provisioned for this work. Therefore the journey "authenticated customer → catalogue → product → quantity → carton → cart → estimate → submission validation" could **not** be run live. Live submission, estimate totals and RLS behaviour are untested here.

## Verdict
G08 stays **BLOCKED** on one dependency: Core must implement and publish the packing-profile projection (and Operations must supply packing-master data) in an environment with test buyer credentials. No Core patch was written: a Core migration needs Mission Control assignment and a protected merge, and the specification is already reviewable. The Buyer-side seam (`getCartonSupport`) stays "unavailable" so nothing renders in production.

Bind the two RPCs in `carton-profile-source.ts` through `normalizePackingContract`; supply `priceUomByProduct` from `buyer_product_prices_v1`; run `NONPROD_INTEGRATION_TEST_PLAN.md` (critical scenarios must PASS); keep geometry pending until Operations signs the physical gate.
